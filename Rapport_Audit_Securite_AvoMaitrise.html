1. Synthèse Exécutive

Une analyse approfondie du code source, de la configuration de sécurité (Spring Security, Keycloak, JWT), des contrôleurs REST, de la gestion des données sensibles et de l'architecture frontend Angular a été réalisée. Bien que l'architecture technique repose sur des socles solides (OAuth2/OIDC avec Keycloak, Liquibase, Hibernate), plusieurs vulnérabilités critiques et majeures ont été identifiées et requièrent une correction immédiate pour garantir la confidentialité des données des clients et la conformité légale (Secret professionnel, RGPD, KYC/AML).

3. Analyse Technique Détaillée des Vulnérabilités

Critique 1. Profil « Dev » par défaut désactivant toute sécurité
CWE-306 : Missing Authentication

Dans application.properties, la propriété par défaut est spring.profiles.active=dev. La classe DevSecurityConfig.java associée applique : 

http.authorizeHttpRequests(auth -> auth.anyRequest().permitAll());

Impact : Si le conteneur ou le serveur démarre sans variable d'environnement SPRING_PROFILES_ACTIVE=prod, l'intégralité des endpoints de l'API (dossiers, clients, documents, factures, utilisateurs) est accessible anonymement sans aucun token JWT.

Remédiation : Remplacer le profil par défaut par un profil sécurisé et restreindre DevSecurityConfig uniquement aux tests unitaires mockés.

Critique 2. Absence d'autorisations RBAC sur les contrôleurs REST & Risque IDOR
CWE-285 : Improper Authorization / CWE-639 : IDOR

Bien que @EnableMethodSecurity(prePostEnabled = true) soit activé dans SecurityConfig.java, aucun contrôleur REST n'utilise d'annotation @PreAuthorize.

Impact : N'importe quel utilisateur disposant d'un compte simple (ex: stagiaire ou secrétaire) peut appeler :

  • POST /api/users/{id}/reset-password : Réinitialiser le mot de passe de l'administrateur du cabinet.
  • PUT /api/users/{id}/disable : Désactiver des comptes utilisateurs.
  • PUT /api/cabinet-profile : Modifier les coordonnées bancaires, taux de TVA et paramètres légaux.
  • DELETE /api/invoices/{id} ou DELETE /api/clients/{id} : Supprimer n'importe quel enregistrement sans vérification de droits ni d'appartenance.

Remédiation : Ajouter des vérifications d'autorité systématiques sur tous les contrôleurs :

@PreAuthorize("hasRole('ADMIN')")
@PostMapping("/{id}/reset-password")
public ResponseEntity<String> resetPassword(@PathVariable Long id) { ... }
Critique 3. Divulgation de Stack Traces internes (Information Disclosure)
CWE-209 : Information Exposure Through Error Message

Dans GlobalExceptionHandler.java (lignes 63-66), les exceptions de type Throwable capturent la stack trace complète et la renvoient en texte brut dans le corps de la réponse HTTP 500 : 

java.io.StringWriter sw = new java.io.StringWriter();
ex.printStackTrace(new java.io.PrintWriter(sw));
return ResponseEntity.status(HttpStatus.INTERNAL_SERVER_ERROR).body(sw.toString());

Impact : Fuite critique d'informations sur l'infrastructure (schéma de la base de données, requêtes Hibernate en échec, versions de librairies, chemins système absolus Windows/Linux).

Remédiation : Renvoyer un objet JSON d'erreur standardisé {"error": "Erreur interne", "timestamp": ...} et journaliser la stack trace uniquement dans les logs sécurisés du serveur.

Élevée 4. Endpoints Actuator exposés publiquement sans restriction
CWE-200 : Exposure of Sensitive Information

Dans application.properties : management.endpoints.web.exposure.include=* expose tous les endpoints Actuator. Dans SecurityConfig.java, la règle // .requestMatchers("/actuator/**").hasAnyRole("super_admin", "admin") est désactivée.

Impact : Un attaquant accédant à /actuator/env ou /actuator/heapdump peut récupérer l'ensemble des clés secrètes en mémoire, les sessions utilisateurs et la configuration.

Remédiation : Restreindre l'exposition à health,info et exiger ROLE_ADMIN pour tout accès Actuator.

Élevée 5. Configuration CORS trop permissive
CWE-942 : Permissive Cross-Origin Resource Sharing

Dans CorsConfig.java, allowedOriginPatterns("*") est configuré avec allowCredentials(true).

Impact : N'importe quel domaine malveillant ouvert dans le navigateur d'un avocat peut envoyer des requêtes authentifiées à l'API et lire les réponses.

Remédiation : Restreindre explicitement les origines autorisées aux domaines du cabinet (ex: https://si-legal.duckdns.org, http://localhost:4200).

Élevée 6. Mots de passe et secrets codés en dur dans le code source
CWE-798 : Use of Hard-coded Credentials

Le fichier application.properties contient en clair le secret administrateur Keycloak, la clé API Yente et le mot de passe SMTP. Dans UserService.java:L61, le mot de passe temporaire par défaut est statique : "AvoMaitrise@123".

Remédiation : Injecter tous les secrets via des variables d'environnement et générer un mot de passe aléatoire cryptographique fort pour chaque nouvel utilisateur créé.

Moyenne 7. Absence d'Angular Route Guards côté Frontend
Frontend Access Control

Dans app.routes.ts, aucune route ne déclare canActivate: [authGuard] ou canActivate: [roleGuard]. Un utilisateur peut afficher les écrans de configuration et d'administration.

Remédiation : Implémenter un AuthGuard et un RoleGuard s'appuyant sur KeycloakService.getUserRoles().

4. Plan d'Action & Feuille de Route de Remédiation

  • 🔴 Priorité 0
    (Immédiat)
    Correction de la fuite de Stack Traces & Sécurisation Globale
    1. Nettoyer GlobalExceptionHandler.java pour renvoyer des réponses JSON d'erreur génériques sans stack trace.
    2. Configurer SecurityConfig.java pour verrouiller /actuator/** et ajouter les en-têtes HTTP de sécurité (CSP, HSTS, X-Frame-Options).
    3. Restreindre CorsConfig.java aux domaines stricts autorisés.
  • 🟠 Priorité 1
    (Sous 48h)
    Mise en place du Contrôle d'Accès RBAC & Protection DTO
    1. Ajouter les annotations @PreAuthorize sur UserController, CabinetProfileController, etc.
    2. Sécuriser UserDTO.java avec @JsonProperty(access = JsonProperty.Access.WRITE_ONLY) sur tempPassword.
    3. Externaliser les secrets de application.properties vers des variables d'environnement.
  • 🟡 Priorité 2
    (Sous 1 semaine)
    Angular Guards & Validation des Données
    1. Créer AuthGuard et RoleGuard dans Angular et protéger les routes dans app.routes.ts.
    2. Ajouter les annotations Jakarta Bean Validation (@Valid, @NotBlank, @Size, @PositiveOrZero) sur tous les DTOs backend.
