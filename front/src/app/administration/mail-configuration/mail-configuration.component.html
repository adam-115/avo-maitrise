Google Workspace / Gmail

Scopes demandés : gmail.readonly (lecture seule) + calendar.events (calendrier bidirectionnel).

Guide Administrateur — Configurer Gmail & Google Calendar
Ouvrir Google Cloud Console ↗
  1. Créer un projet : dans Google Cloud Console, créez un projet (ex. Avo-Maitrise).
  2. Activer les 2 APIs : allez dans API et services → Bibliothèque, puis activez Gmail API et Google Calendar API.
  3. Configurer l'écran de consentement OAuth : dans Google Auth Platform → Audience, choisissez Externe (ou Interne si tout le cabinet est sous Google Workspace), renseignez le nom de l'application et votre e-mail de support.
    Important (Erreur 403 access_denied) : tant que l'application est en statut « Test », ajoutez chaque adresse Gmail autorisée dans la section Utilisateurs test (jusqu'à 100 comptes), ou publiez l'application en production.
  4. Créer un identifiant OAuth 2.0 : dans Clients → Créer un client, sélectionnez le type Application Web.
  5. Ajouter l'URI de redirection autorisée : dans la section URI de redirection autorisés, collez exactement cette URL :
    {{ config.googleRedirectUri }}
  6. Finaliser ici : copiez le Client ID et le Client Secret dans les champs ci-dessous, activez le module et cliquez sur Enregistrer. Chaque avocat pourra ensuite cliquer sur Gmail / Google dans Messagerie.

Microsoft 365 / Outlook

Scopes demandés : Mail.Read (lecture seule) + Calendars.ReadWrite (calendrier bidirectionnel).

Guide Administrateur — Configurer Outlook & Microsoft 365
Ouvrir Microsoft Entra ID ↗
  1. Inscrire une application : ouvrez Microsoft Entra Admin Center → Identité → Applications → Inscriptions d'applications → Nouvelle inscription (ex. Avo-Maitrise).
  2. Types de comptes pris en charge : choisissez Comptes dans un annuaire d'organisation quelconque et comptes Microsoft personnels (cela permet d'utiliser Tenant ID = common pour tous les comptes Outlook/M365).
  3. URI de redirection : sélectionnez la plateforme Web et collez exactement cette URL :
    {{ config.microsoftRedirectUri }}
  4. Créer un Client Secret : dans le menu Certificats & secrets → Secrets client → Nouveau secret client.
    Attention : copiez immédiatement la colonne Valeur (et non l'ID du secret), car Microsoft ne l'affiche qu'une seule fois.
  5. Ajouter les autorisations Microsoft Graph : dans Autorisations de l'API → Ajouter une autorisation → Microsoft Graph → Autorisations déléguées, ajoutez :
    User.Read Mail.Read Calendars.ReadWrite offline_access
  6. Finaliser ici : dans la vue d'ensemble de l'application Azure, copiez l'ID d'application (client), collez la Valeur du secret et laissez Tenant ID = common (ou l'ID de votre tenant si usage strictement interne), puis cliquez sur Enregistrer.
