2. Les deux modèles d'IA et Qdrant : qui fait quoi

Le point clé : il y a deux modèles différents, qui ne font pas le même travail, et Qdrant fait le lien entre eux. C'est le principe du RAG (Retrieval-Augmented Generation) : on cherche d'abord les bons passages, puis on demande au modèle d'écrire à partir d'eux.

RelationExplication
nomic-embed-text ↔ QdrantToujours ensemble. Avec Spring AI, c'est le VectorStore qui appelle lui-même l'EmbeddingModel, à l'écriture comme à la recherche : le même modèle est donc forcément utilisé des deux côtés. Changer de modèle d'embedding impose une nouvelle collection et une réindexation.
Qdrant → qwenQdrant fournit la matière (les extraits), qwen rédige. Qdrant ne génère rien ; qwen ne cherche rien et ne « connaît » pas les dossiers.
qwen ↔ OpenAI / GeminiLe modèle de chat est interchangeable depuis l'écran admin (table ai_configuration). Les embeddings, eux, restent toujours sur Ollama.
MySQL → qwenDans le chat général, qwen décide d'appeler des méthodes Java (@Tool de AvoAiTools) qui lisent MySQL, puis utilise le résultat.
Ressources : seule la génération (qwen) est gourmande et bénéficie d'un GPU. L'embedding et Qdrant sont légers et tournent sans difficulté sur un VPS sans GPU.

3. Configuration du modèle actif (écran admin)

Le choix du fournisseur et du modèle de chat est stocké en base, dans la table ai_configuration. Une seule ligne est active à la fois. Si aucune ligne n'est active, l'IA est désactivée (aucune indexation, aucun appel).

4. Infrastructure Spring AI

Avec Spring AI, l'infrastructure n'est plus écrite à la main : les starters créent automatiquement les beans à partir de application.properties. Il ne reste dans le code que les pools de threads et le chargement des prompts.

5. Indexation d'un document (upload → Qdrant)

À chaque upload, le document est enregistré normalement (MySQL + MinIO), puis indexé en arrière-plan, une fois la transaction validée. L'utilisateur n'attend pas la vectorisation. qwen n'intervient pas dans cette étape.

Classes impliquées

ClasseRôle dans l'indexation
DocumentService (front)Envoie le document à POST /api/documents.
DocumentControllerDélègue à DocumentService.create(dto).
DocumentService (back)Upload MinIO, sauvegarde MySQL, puis enregistre un TransactionSynchronization.afterCommit() qui lance l'indexation.
RAGDocumentServiceingestDocumentIntoQdrant() (@Async("aiIngestionExecutor")) → méthode privée ingest().
MinioServiceuploadFile() puis getFileStream() pour relire le fichier.
TikaDocumentReaderExtrait le texte brut du PDF / Word.
TokenTextSplitterDécoupe en morceaux d'environ 150 tokens (≈ 500 à 600 caractères).
VectorStoredelete("document_id == 'X'") puis add(morceaux) : calcule les embeddings et écrit dans Qdrant.

Métadonnées stockées avec chaque morceau

document_id, nom_fichier, type_document (DOSSIER, JURISPRUDENCE…), pays, dossier_id, dossier_nom, client_id, client_nom. Elles permettent de chercher uniquement dans les pièces d'un dossier (dossier_id == '1494') ou dans la jurisprudence d'un pays (type_document == 'JURISPRUDENCE' && pays == 'FRANCE').

6. Analyse stratégique d'un dossier (RAG + streaming)

C'est le flux principal, déclenché depuis l'onglet stratégie d'un dossier. Le backend ne laisse pas le modèle choisir ses outils (trop lent) : il fait lui-même les deux recherches, remplit le prompt strategie.txt, puis diffuse la réponse mot par mot au front via SSE (Server-Sent Events). Le flux de tokens est un Flux<String> fourni par ChatClient.stream().

PaysPays du client du dossier (France, FR, LU…) → valeur connue pour le filtre, défaut FRANCE.

8. Assistant général avec outils (tool calling)

Pour /api/ai/chat et /api/ai/analyze, c'est le modèle qui décide quelles méthodes Java appeler. On passe l'objet AvoAiTools au ChatClient (.tools(avoAiTools)) : Spring AI envoie au modèle la description de chaque méthode @Tool, exécute l'outil demandé, renvoie le résultat au modèle, puis récupère la réponse finale. La mémoire de la conversation est gérée par un advisor.

ClasseRôle
AiTesterComponent (front)Envoie {message, sessionId} (UUID par session).
AiService.chatWithTools()ChatClient.prompt().system(prompt).user(msg).tools(avoAiTools).advisors(MessageChatMemoryAdvisor).
MessageChatMemoryAdvisor + MessageWindowChatMemoryMémoire : 20 derniers messages par conversation. Identifiant = utilisateur:sessionId (paramètre ChatMemory.CONVERSATION_ID).
BoundedChatMemoryRepositoryStockage en RAM borné à 500 conversations (remplaçable par JdbcChatMemoryRepository pour garder l'historique en base).
AvoAiToolsOutils @Tool / @ToolParam : searchClients, getClientDetails, getRecentDossiers, getInvoicesForClient, getClientAmlMatches, getRecentDocuments, summarizeDossier, searchDocumentsInDossier, searchJurisprudence.
Services métierClientService, DossierService, InvoiceService, ScreeningMatchService, DocumentService, AiDossierSummaryService, RAGDocumentService.

10. Resynchronisation et suppression de documents

ActionFlux de classes
Réindexer tous les documents
POST /api/ai/sync-all-documents		AiController.syncAllDocuments() → pour chaque document ayant un fichier : RAGDocumentService.ingestDocumentIntoQdrantSync() → ingest(). L'ancienne version est supprimée avant l'écriture : relancer la synchro ne crée pas de doublons (vérifié : 1 seul point après deux indexations).
Supprimer un document
DELETE /api/documents/{id}		DocumentController → DocumentService.delete() → MinIO + MySQL → RAGDocumentService.removeDocumentFromQdrant() → VectorStore.delete("document_id == 'id'"). Une erreur Qdrant est journalisée sans bloquer la suppression.
Changer de modèle d'embeddingModifier AI_EMBEDDING_MODEL et QDRANT_COLLECTION (nouvelle collection, créée à la bonne dimension au démarrage), puis lancer la synchro.
Migration depuis LangChain4j : l'ancienne collection avo_docs_collection n'est plus lue (format différent). Après le déploiement, lancer POST /api/ai/sync-all-documents pour remplir avo_documents, puis supprimer l'ancienne collection.

Tester l'IA en local

Un test de bout en bout (SpringAiLocalSmokeTest) vérifie l'indexation, l'absence de doublons, la recherche filtrée, la suppression, le streaming, le tool calling et la mémoire contre Ollama et Qdrant locaux. Il est désactivé par défaut :

$env:AI_SMOKE_TEST="true"; mvn test -Dtest=SpringAiLocalSmokeTest
À retenir pour le déploiement : Ollama doit toujours être joignable pour les embeddings, même si le chat passe par OpenAI ou Gemini. Installer nomic-embed-text (ollama pull nomic-embed-text) et le modèle de chat configuré en base si le provider est OLLAMA.
