1. Ce qui a changé

Il y a eu deux étapes : d'abord des corrections de bugs dans la version LangChain4j, puis une migration complète vers Spring AI, qui a remplacé une partie de ces corrections. Le tableau compare le code de départ à l'état final.

2. Le rôle de chaque classe

La configuration (sans code Java)

application.properties (section Spring AI) dit à Spring AI :

  • de ne pas créer de modèle de chat automatiquement (spring.ai.model.chat=none), parce que ce modèle vient de la base ;
  • d'utiliser Ollama pour les embeddings (nomic-embed-text) ;
  • où trouver Qdrant (hôte, port 6334, collection avo_documents) et de créer la collection si elle n'existe pas.

Les starters Spring AI lisent ces propriétés au démarrage et créent deux objets utilisés par le reste du code :

  • EmbeddingModel : transforme un texte en vecteur via Ollama ;
  • VectorStore : la porte d'entrée vers Qdrant. Il sait ajouter des passages (en calculant lui-même leurs vecteurs), chercher les plus proches avec un filtre, et supprimer selon un filtre.

RAGConfig

Rôle : créer les deux pools de threads réservés à l'IA.

  • aiIngestionExecutor (1 à 2 threads) : indexer les documents en arrière-plan. Il est limité pour ne pas saturer Ollama quand on uploade beaucoup de fichiers d'un coup ; les autres attendent dans une file.
  • aiStreamingExecutor (2 à 4 threads) : préparer les analyses stratégiques sans bloquer le thread de la requête HTTP.

Quand : au démarrage. Utilisé par : RAGDocumentService (indexation) et AiService (streaming).

AiConfigurationService

Rôle : fabriquer le modèle de chat à partir de la ligne active de la table ai_configuration.

  • isAiEnabled() : y a-t-il une configuration active ? Sinon, l'IA est considérée comme désactivée.
  • buildChatModel() : lit la configuration et construit un ChatModel Spring AI :
    • OLLAMA donne un OllamaChatModel (URL et modèle saisis dans l'écran admin) ;
    • OPENAI donne un OpenAiChatModel ;
    • GEMINI donne aussi un OpenAiChatModel, pointé sur l'API de Google compatible OpenAI.
    Le délai de lecture HTTP suit timeoutMinutes, et la température suit temperature.

Pourquoi reconstruire à chaque appel : si l'admin passe d'Ollama à OpenAI, c'est pris en compte immédiatement, sans redémarrage.

Appelé par : AiService (à chaque usage de l'IA) et RAGDocumentService (vérifie isAiEnabled() avant d'indexer).

Prompts

Rôle : lire un fichier prompts/xxx.txt et remplacer les variables {{nom}}. Exemple : render("strategie", "pays", "FRANCE", "documents", ...) renvoie le texte complet prêt à envoyer.

Pourquoi un simple chercher-remplacer : les documents juridiques peuvent contenir des accolades {}, qui casseraient un moteur de templates. Le fichier est mis en cache après la première lecture.

Appelé par : AiService.

Pays

Rôle : transformer un pays saisi librement (« France », « FR », « belgique ») en une valeur connue (FRANCE, BELGIQUE…), avec FRANCE par défaut.

Pourquoi :

  1. Les documents de jurisprudence sont classés avec ces valeurs exactes : il faut la même orthographe pour que le filtre trouve quelque chose.
  2. La sécurité : ce texte est inséré dans un filtre Qdrant. En n'acceptant que des valeurs connues, une valeur bizarre (envoyée par le modèle, par exemple) ne peut pas détourner le filtre.

Appelé par : AiService (pays du client du dossier) et AvoAiTools (pays demandé par le modèle).

RAGDocumentService (le cœur du RAG)

Rôle : tout ce qui touche à Qdrant.

Indexer un document. ingestDocumentIntoQdrant(id) en arrière-plan (@Async), ingestDocumentIntoQdrantSync(id) en mode bloquant. Étapes de ingest() :

  1. Si l'IA est désactivée, s'arrêter.
  2. Charger le Document depuis MySQL.
  3. Lire le fichier dans MinIO (MinioService.getFileStream).
  4. Extraire le texte avec TikaDocumentReader (PDF, Word…).
  5. Ajouter les métadonnées : document_id, dossier_id, type_document, pays, client_id, nom_fichier…
  6. Supprimer l'ancienne version du document dans Qdrant, pour éviter les doublons.
  7. Découper en passages d'environ 150 tokens (TokenTextSplitter).
  8. vectorStore.add(passages) : Spring AI calcule le vecteur de chaque passage via Ollama, puis écrit dans Qdrant.

Quand : après chaque upload, et lors d'une resynchronisation complète.

Retirer un document. removeDocumentFromQdrant(id) appelle vectorStore.delete("document_id == 'id'"), avant une réindexation et à la suppression d'un document. Une erreur Qdrant est journalisée sans bloquer : on ne veut pas empêcher la suppression d'un document parce que Qdrant est momentanément indisponible.

Chercher.

  • searchInDossier(dossierId, question) : les 5 passages les plus proches, uniquement dans ce dossier, avec un score minimum de 0,5.
  • searchJurisprudence(pays, question) : les 4 passages les plus proches parmi la jurisprudence du pays.

Appelé par : DocumentService (indexation et retrait), AiController (resynchronisation), AvoAiTools (recherches).

AvoAiTools

Rôle : la « boîte à outils » que le modèle peut utiliser. Chaque méthode annotée @Tool(description = ...) est décrite au modèle, qui peut décider de l'appeler. @ToolParam décrit chaque paramètre (« Identifiant numérique du dossier »…) pour qu'il les remplisse correctement.

AiService (le chef d'orchestre)

Rôle : tous les usages de l'IA. Le principe est toujours le même : charger le prompt, ajouter le contexte, appeler le modèle via ChatClient. ChatClient est l'API de Spring AI pour parler au modèle : .prompt().system(...).user(...).call() répond d'un bloc, .stream() répond en flux.

Le streaming, étape par étape :

  1. La tâche part sur aiStreamingExecutor. La requête HTTP rend la main tout de suite, le flux SSE est ouvert.
  2. On cherche le pays du client (Pays.normalize).
  3. On appelle searchDocumentsInDossier et searchJurisprudence.
  4. On remplit strategie.txt avec ces passages.
  5. chatClient().prompt().user(prompt).stream().content() produit un Flux<String> : un morceau de texte à la fois.
  6. Pour chaque morceau : on l'ajoute au texte complet et on l'envoie au front en SSE ({"token": "..."}).
  7. À la fin du flux : on sauvegarde la stratégie dans Dossier.aiStrategy, puis on envoie l'événement DONE.
  8. En cas d'erreur : on la journalise et on ferme le flux en erreur.

La mémoire du chat :

  • MessageChatMemoryAdvisor (fourni par Spring AI) ajoute automatiquement l'historique avant d'appeler le modèle, et enregistre la question et la réponse après.
  • La clé est utilisateur:sessionId, pour que deux utilisateurs ne voient jamais l'historique l'un de l'autre.
  • BoundedChatMemoryRepository stocke ces historiques en RAM, avec 500 conversations au maximum (les plus anciennes sont oubliées). Ils sont perdus au redémarrage ; on pourra le remplacer par une version JDBC pour les garder en base.

Les classes inchangées qui jouent un rôle

  • AiController : reçoit les requêtes /api/ai/*, vérifie les paramètres et délègue à AiService. Pour le streaming, il crée le SseEmitter (15 minutes maximum). Pour /sync-all-documents, il boucle sur tous les documents et appelle RAGDocumentService.
  • AiConfigurationController : CRUD de la table ai_configuration pour l'écran admin.
  • DocumentService : après l'enregistrement d'un upload, il programme l'indexation après le commit de la transaction, pour que le thread d'indexation trouve bien le document en base. À la suppression, il appelle removeDocumentFromQdrant.
  • AiDossierSummaryService : construit un résumé texte d'un dossier (tâches, activités, notes, rendez-vous, facturation) pour l'outil summarizeDossier.

SpringAiLocalSmokeTest

Rôle : vérifier toute la chaîne contre Ollama et Qdrant en local : indexation, absence de doublons, filtre, suppression, streaming, outils et mémoire. Il travaille dans une collection de test, supprimée à la fin.

Désactivé par défaut, pour ne pas faire échouer les builds sur une machine sans Ollama. Pour le lancer :

$env:AI_SMOKE_TEST="true"; mvn test -Dtest=SpringAiLocalSmokeTest

3. Qui appelle qui, et quand

Au démarrage

Spring Boot
 ├─ starter Ollama  → crée EmbeddingModel (nomic-embed-text)
 ├─ starter Qdrant  → crée la collection avo_documents si absente → crée VectorStore
 └─ RAGConfig       → crée aiIngestionExecutor, aiStreamingExecutor

À l'upload d'un document

Front → DocumentController → DocumentService.create()
          ├─ MinioService.uploadFile()
          ├─ save en MySQL → réponse immédiate au front
          └─ après commit → RAGDocumentService.ingestDocumentIntoQdrant()   [thread AI-Ingest]
                ├─ AiConfigurationService.isAiEnabled()
                ├─ MinioService.getFileStream() → TikaDocumentReader
                ├─ VectorStore.delete(ancienne version)
                └─ TokenTextSplitter → VectorStore.add() → Ollama (vecteurs) → Qdrant

Au clic sur « Analyser la stratégie »

DossierStrategieComponent (EventSource) → AiController.analyzeStream()
  └─ AiService.analyzeDossierStrategyStream()   [thread AI-Stream]
        ├─ DossierRepository → pays du client → Pays.normalize()
        ├─ AvoAiTools.searchDocumentsInDossier() → RAGDocumentService → VectorStore → Qdrant
        ├─ AvoAiTools.searchJurisprudence()      → RAGDocumentService → VectorStore → Qdrant
        ├─ Prompts.render("strategie")
        ├─ AiConfigurationService.buildChatModel() → ChatClient.stream()
        │     └─ chaque token → SSE vers le front
        └─ fin → DossierRepository.save(aiStrategy) → événement DONE

Pour une question dans le chat général

AiTesterComponent → AiController.chat() → AiService.chat()
  └─ ChatClient (system + message + outils + mémoire)
        ├─ le modèle demande un outil → AvoAiTools.searchClients() → ClientService → MySQL
        ├─ le résultat est renvoyé au modèle → réponse finale
        └─ la mémoire enregistre l'échange

Pour une question de suivi sur la stratégie

DossierStrategieComponent → AiController.chatDossier() → AiService.chatDossierStrategy()
  ├─ DossierRepository → stratégie sauvegardée → SystemMessage
  ├─ historique du front → UserMessage / AssistantMessage
  ├─ AiConfigurationService.buildChatModel() → ChatModel.call()
  └─ DossierRepository.save(aiChatHistory)

À la suppression d'un document

DocumentController → DocumentService.delete() → MinIO + MySQL
  └─ RAGDocumentService.removeDocumentFromQdrant() → VectorStore.delete()

4. À faire au déploiement

  1. Réindexer les documents : Spring AI n'utilise pas le même format que LangChain4j dans Qdrant, donc la nouvelle collection avo_documents est vide. Lancer POST /api/ai/sync-all-documents, puis supprimer l'ancienne collection avo_docs_collection.
  2. Ollama doit rester joignable pour les embeddings, même si le chat passe par OpenAI ou Gemini : installer nomic-embed-text (ollama pull nomic-embed-text), et le modèle de chat configuré en base si le provider est OLLAMA.
  3. Variables d'environnement : OLLAMA_BASE_URL, AI_EMBEDDING_MODEL, QDRANT_HOST, QDRANT_GRPC_PORT, QDRANT_COLLECTION (valeurs par défaut dans application.properties).

Les diagrammes de séquence détaillés de chaque flux sont dans le document « Intégration de l'IA dans Avo-Maîtrise » (Integration_IA_Avo-Maitrise.pdf).
